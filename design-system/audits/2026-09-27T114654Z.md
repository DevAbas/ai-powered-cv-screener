# Design Token Architecture Audit

- Project: ai-powered-cv-screener (`03b7f3e`), with uncommitted changes
- Date: 2026-09-27
- Profile: terrazzo-tailwind-v4
- Token format: W3C Design Tokens (DTCG) 2025.10: 10 *.tokens.json files behind a resolver with sets foundation and semantic and one modifier, theme (light default, dark)
- Rules document: `DESIGN.md`

## Summary

| Part | Status | Summary |
|---|---|---|
| naming | met | Roles are named by purpose in kebab-case in both themes, and one mapping from id to class and variable (DESIGN.md, Overview: Reading the tokens) is enforced by the contract check and the token-classes lint. |
| tiers | met | Roles alias the palette or carry a recorded rule, code reads only roles, and the contract names the roles of every component in src/components. |
| format | met | The tokens parse as DTCG 2025.10 through Terrazzo, both themes define the same 24 roles, and both stylesheets are built by Terrazzo behind a --check staleness gate and an edit-denying hook. |
| docs | met | Every colour role carries its definition as $description in both themes, and DESIGN.md holds only the rules for using the tokens, citing ids, with no values and no definitions. |

Findings: 0 error, 0 warning, 0 info.
